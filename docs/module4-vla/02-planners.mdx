# Natural-language Planners for Robots: From Intent to Action Sequences (LLMs & Task Planning)

In the previous chapter, we learned how to extract a structured intent (e.g., "pick_up blue_block") from a human's voice command. The next crucial step in creating an intelligent, interactive robot is to translate this high-level intent into a sequence of low-level, executable robot actions. This is the domain of **natural language planning**, where Large Language Models (LLMs) are proving to be incredibly powerful tools.

## 1. The Challenge of Robot Task Planning

Traditional robot task planning often relies on predefined state-space search algorithms (e.g., STRIPS, PDDL) or finite state machines. While effective for well-defined, constrained problems, these approaches can be brittle and hard to scale when dealing with the vast, open-ended nature of natural language commands and the complexities of real-world environments.

LLMs, with their vast knowledge base and reasoning capabilities, offer a more flexible and robust approach to this challenge. They can:
*   **Decompose Complex Goals**: Break down a high-level command into a series of simpler sub-tasks.
*   **Reason about the World**: Leverage their understanding of physical properties, object affordances, and common sense to generate plausible action sequences.
*   **Adapt to Ambiguity**: Handle slightly ambiguous or underspecified commands by making reasonable inferences.

### LLM Planning Pipeline Overview

## 2. LLM-based Task Planning

The core idea is to prompt an LLM to generate a plan—a sequence of executable actions—that will achieve the user's intent. This typically involves **prompt engineering**, where we craft a detailed instruction for the LLM.

### Key Elements of an LLM Planning Prompt:

1.  **System Role**: Define the LLM's persona (e.g., "You are a robot task planner.").
2.  **Available Actions**: Provide a list of functions/actions the robot can perform, including their parameters and preconditions (e.g., `navigate(destination: str)`, `grasp(object_name: str)`).
3.  **Current Robot State**: Optionally, provide a simplified representation of the robot's current state and environment.
4.  **User Goal**: The extracted intent and entities from the NLU step.
5.  **Output Format**: Specify the desired format for the plan (e.g., a Python list of function calls, a JSON array).

### Conceptual Example: LLM as a Planner

Let's assume our robot can perform the following simplified ROS 2 actions:
*   `navigate_to_location(location: str)`
*   `detect_object(object_name: str)`
*   `pick_up_object(object_name: str)`
*   `place_object(location: str)`

**Prompting an LLM (Conceptual):**
```python
# code/module4/llm_planner_conceptual.py
# This is a conceptual example. Replace with actual LLM API calls (e.g., OpenAI, Gemini, Llama 2)

def generate_robot_plan(intent_data):
    """
    Conceptual function to generate a robot action plan using an LLM.
    """
    intent = intent_data.get("intent")
    entities = intent_data.get("entities", {})

    available_actions = """
    - navigate_to_location(location: str): Navigate the robot to a specified location.
    - detect_object(object_name: str): Detect a specific object in the current field of view.
    - pick_up_object(object_name: str): Pick up a detected object.
    - place_object(location: str): Place the held object at a specified location.
    """

    user_goal = f"Intent: {intent}, Entities: {entities}"

    prompt = f"""
You are a helpful robot task planner. Your goal is to generate a sequence of low-level robot actions
    to achieve a high-level user goal.

    Available ROS 2 Actions:
    {available_actions}

    Robot's Current Environment/Knowledge (simplified):
    - Locations: "kitchen", "living_room", "bedroom"
    - Objects: "red_block", "blue_block", "green_block" (Assume they are at known locations for planning simplicity)

    User Goal: {user_goal}

    Generate a plan as a Python list of action function calls. Ensure the plan is executable
    and respects the order of operations. If a step cannot be performed with available actions,
    use a placeholder or indicate an error.

    Example:
    User Goal: Intent: navigate_to, Entities: {{'destination': 'kitchen'}}
    Plan:
    [
      "navigate_to_location(location='kitchen')"
    ]

    User Goal: Intent: pick_up, Entities: {{'object': 'blue_block'}}
    Plan:
    [
      "navigate_to_location(location='living_room')", # Assume blue block is in living room
      "detect_object(object_name='blue_block')",
      "pick_up_object(object_name='blue_block')"
    ]

    Now, generate the plan for the User Goal: {user_goal}
    Plan:
    """
    
    print(f"--- LLM Prompt ---")
    print(prompt)
    print(f"--- LLM Response (Simulated) ---")

    # Simulate LLM response
    if intent == "navigate_to" and entities.get("destination") == "kitchen":
        simulated_response = """
        [
          "navigate_to_location(location='kitchen')"
        ]
        """
    elif intent == "pick_up" and entities.get("object") == "blue_block":
        simulated_response = """
        [
          "navigate_to_location(location='living_room')",
          "detect_object(object_name='blue_block')",
          "pick_up_object(object_name='blue_block')"
        ]
        """
    else:
        simulated_response = "[]" # Empty or error plan
    
    print(simulated_response)
    
    import ast
    try:
        return ast.literal_eval(simulated_response)
    except (ValueError, SyntaxError) as e:
        print(f"Error parsing LLM response: {e}")
        return []

if __name__ == "__main__":
    intent_data_1 = {"intent": "navigate_to", "entities": {"destination": "kitchen"}}
    plan_1 = generate_robot_plan(intent_data_1)
    print(f"\nPlan for {intent_data_1}: {plan_1}")

    intent_data_2 = {"intent": "pick_up", "entities": {"object": "blue_block"}}
    plan_2 = generate_robot_plan(intent_data_2)
    print(f"\nPlan for {intent_data_2}: {plan_2}")
```

## 3. Integrating with ROS 2 Action Sequences

Once the LLM generates a plan (e.g., a list of function calls), a Python script (often a ROS 2 node) needs to parse this plan and execute the corresponding ROS 2 Actions.

### Plan Execution Node (Conceptual)

This node would act as the central orchestrator, connecting to various ROS 2 Action Servers (e.g., for navigation, manipulation, perception) and sending them goals as dictated by the LLM's plan.

## 4. Building Conversational Humanoids

By combining Whisper (ASR), NLU (LLM-driven intent extraction), and LLM-based planning with ROS 2 action execution, we can create conversational humanoids that:
*   Listen to human commands.
*   Understand the underlying intent.
*   Generate complex action sequences.
*   Execute these actions in the physical world.

This multi-modal integration allows for a much richer and more intuitive human-robot interaction experience.

## Conclusion

LLMs are revolutionizing robot task planning, enabling robots to interpret complex natural language commands and generate flexible, executable action sequences. Integrating these powerful models with ROS 2 allows for the creation of highly intelligent and conversational humanoid robots, pushing the boundaries of Physical AI into new realms of human-robot collaboration.
